# Движок упражнений

`ExerciseRenderer` принимает публичный JSON, проверяет его через `parseExercise` и выбирает компонент из `exerciseRegistry`. Пример формата:

```json
{
  "id": "00000000-0000-4000-8000-000000000001",
  "kind": "multiple_choice",
  "prompt": "Выберите подходящие утверждения.",
  "options": ["Утверждение A", "Утверждение B", "Утверждение C"],
  "difficulty": 2,
  "position": 0
}
```

Базовые типы: `single_choice`, `multiple_choice`, `numeric`, `text`, `long_text`. У вариантов выбора 2–12 уникальных непустых options, у остальных options пустой. Правильные ответы, объяснения и неизвестные поля в этом JSON запрещены runtime-валидатором. Ключи по-прежнему находятся в отдельной закрытой таблице и авторском API каталога, не в renderer.

Для интерактивного режима передаётся зависимость `submit(exercise, answer, requestID)`. Без неё renderer показывает безопасный read-only preview. `LessonExercises` соединяет renderer с текущей cookie-сессией и API, восстанавливает последние ответы для конкретной версии и показывает автору очередь ручной проверки. Новый API-клиент низкого уровня не создаётся: используется существующий `request`.

Ответ: `{ "selected": ["строка варианта"] }` для выбора, `{ "value": "текст" }` для остальных типов. Renderer валидирует ввод, но никогда не сравнивает его с закрытым ключом. Общие состояния: idle, checking, correct, incorrect, needs_review. Первые четыре типа автоматически получают correct/incorrect от сервера; long_text получает needs_review, затем решение преподавателя. HTTP-ошибка не считается неверным ответом. При изменении ответа создаётся новый requestID; неизменённый ответ после сетевой ошибки повторяется с прежним ID.

## Серверная политика

- `POST /api/v1/catalog/lessons/{lesson}/exercises/{exercise}/attempts`: student only; `{version_id, request_id, answer}`. Версия должна быть текущей опубликованной. Повтор той же попытки возвращает её сохранённый результат; другая нагрузка с тем же nonce или новая отправка в устаревшую версию даёт 409. Проверка привязана к физическому упражнению в запечатанном снимке, а не к редактируемому черновику.
- `GET /api/v1/catalog/lessons/{lesson}/attempts?limit=…&offset=…`: ученик видит только свои ответы, автор только ответы своего урока. Доступ ученика отзывается вместе с доступом к материалу; автор сохраняет доступ к истории своего урока. Другие преподаватели не получают историю, даже если могут читать публикацию.
- `PUT /api/v1/catalog/lessons/{lesson}/attempts/{attempt}/review`: автор проверяет только long_text; `{status: "correct" | "incorrect", feedback}`. Повтор одинаковой проверки безопасен, изменение завершённой проверки даёт 409. Reviewer и время задаёт сервер. Уведомления преподавателю об ответе и ученику о проверке создаются в той же транзакции.

Числа: точное сравнение через стандартный Go `math/big.Rat`, без float64. Принимаются знак `+`/`-`/`−`, десятичная точка или запятая, целая дробь со знаками числителя и знаменателя, внешние пробелы и пробелы вокруг `/`. Нулевой знаменатель, выражения, экспоненты, смешанные числа и разделители тысяч запрещены. Ввод ограничен 128 байтами. Короткий текст: до 1000 Unicode-символов, без учёта регистра, внешних и повторных пробелов. Решение: до 20000 символов, сохраняется без нормализации. Для multiple_choice закрытый `answer_key.answer` хранит JSON-массив строк вариантов; порядок выбора при проверке не важен. Для long_text сервер создаёт служебный закрытый ключ вместо правильного ответа.

Новых зависимостей или формульного рендерера нет: для текущего формата достаточно обычного безопасного текста. Импорт HTML, символьная алгебра, файлы решений, агрегированный учебный прогресс, ограничения попыток и изменение завершённых рецензий не реализуются этим модулем.

Задача 05 добавляет сохраняемые прохождения конкретного урока, но не межкурсовую аналитику. `StudentLearning` использует `learningApi` и тот же renderer для восстановления отправленных ответов закреплённой версии, подсказок, истории ошибок и результатов. Сервер управляет идентичностью, номером, временем и проверкой. Контракт и точная политика: [LEARNING_PROGRESS_API.md](../../../../docs/LEARNING_PROGRESS_API.md). Неотправленный текст не является сохранённой попыткой; автономные HTML остаются отдельной teacher-only мастерской.

## Проверки

Из `apps/web`: `pnpm test:exercise-engine` (Node 22+ с type stripping). Go: `go test ./internal/exercise`, интеграция требует отдельную TEST_DATABASE_URL. `apps/web/tests/exercise-engine.e2e.mjs` использует тот же способ запуска Playwright, что и `apps/web/tests/README.md`, с `REPET_E2E_URL=http://127.0.0.1:3002`. Запускать только в отдельной тестовой базе: сценарий создаёт двух пользователей, связь, курс, тему, урок и пять упражнений. Скриншоты: игнорируемая `tmp/task03-exercise-engine`.

## Визуальные типы (04)

Все десять типов используют тот же renderer, авторский редактор, сохранение попыток, ACL и серверную проверку. Публичный `config` описывает только доступные объекты, не целевой ответ. Формальная схема Draft 7: [exercise.schema.json](exercise.schema.json); её использует и OpenAPI. `visual-schema.ts` и Go дополнительно проверяют зависимости полей, кратность шага, уникальность ID/подписей, координаты и ссылки на существующие точки. Неизвестные поля и `null` вместо настроек отвергаются.

| Тип | Публичный config | Ответ ученика |
| --- | --- | --- |
| number_line | Целые min/max в пределах -1000..1000, step 1..100; длина кратна шагу, не более 100 интервалов | `value`: строка целой координаты на заданном шаге |
| grid_select | rows/columns 1..8 | `selected`: уникальные `row:column`, индексация от 0 сверху слева |
| matching | left/right: 2..8 объектов `{id,label}`, одинаковое число с обеих сторон | `selected`: все пары `leftID:rightID`, взаимно однозначно |
| ordering | items: 2..12 объектов `{id,label}` | `selected`: все ID в выбранном порядке |
| geometry point | mode=point, rows/columns 2..8 | Один `x:y`, начало координат снизу слева |
| geometry connect | mode=connect, размер сетки и 2..12 points `{id,label,x,y}` | Уникальные неориентированные рёбра `a:b`, ID внутри ребра отсортированы ASCII |
| geometry select | mode=select, сетка, points и 2..12 objects `{id,label,kind,point_ids}` | Один ID объекта; kind=segment (2 точки) или polygon (3..12) |

ID объектов начинается с латинской буквы, далее буквы/цифры/`_`/`-`, всего до 16 символов. Пустой ответ не отправляется; порядок важен только для ordering. Частичных баллов нет. Закрытый ключ number_line — координата, остальных визуальных типов — JSON-массив строк в формате selected. Объективные ответы оцениваются только сервером по ключу конкретной опубликованной версии. Config копируется в неизменяемую публикацию вместе с упражнением.

Мышь и касание: точка на числовой прямой, клетки/точки сетки, соединения и геометрические объекты реагируют на выбор; сортировка поддерживает mouse drag-and-drop. Доступные альтернативы: range/поле координаты, стрелки сетки с Enter/Space, кнопки и select соответствий, кнопки вверх/вниз и ArrowUp/ArrowDown сортировки, select концов отрезка и radio объектов. Рисование и перемещения локальные; запрос проверки выполняется только по действию ученика. Geometry — ограниченный инструмент сетки, не символьная геометрическая система.

Компоненты: `GridBoard`, `NumberLineInput`, `GridSelectInput`, `MatchingInput`, `OrderingInput`, `GeometryInput`. `visual-exercises.test.mjs` проверяет схемы/Ajv и граничные ответы, `visual-exercises.e2e.mjs` — реальную мышь, клавиатуру, touch и серверный результат семи вариантов. Ajv берётся из существующих dev-зависимостей ESLint; production-зависимостей не добавлено.
