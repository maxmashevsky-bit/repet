# Аналитика учебных результатов

Задания → Успеваемость (`/tasks/progress`). Преподаватель выбирает ученика, обе роли выбирают период до366 включительных дней. Раздел использует существующие learning_attempts/exercise_attempts, hints, assignments и study_sessions. Исходные ответы, закрытые ключи и личная переписка в отчёт не включены. Legacy HTML не считается достоверной статистикой упражнений.

## API

- `GET /api/v1/learning-analytics/students?limit=20&offset=0` — только активные ученики этого преподавателя, пагинация.
- `GET /api/v1/learning-analytics/{studentID}?from=2026-10-01&to=2026-10-30&topic_offset=0&exam_offset=0` — сводка, домашние, темы, дневные данные, история пробников и до5 рекомендаций. Темы и пробники постранично по20. Даты UTC; `to` включителен. По умолчанию последние30дней. Неизвестные или повторяющиеся query-параметры отклоняются.
- `POST /api/v1/learning-analytics/{studentID}/repeat` — преподаватель передаёт `request_id`, `run_id`, `topic_key`, `due_at`. Только актуальные неверные ответы одной темы в доступном преподавателю прохождении → новое practice-назначение с закреплённой версией. Повтор nonce идемпотентен; иной payload409. Чужие run/topic/ученик не открываются. Статистика из браузера не принимается.

Контракт `packages/contracts/openapi/learning-analytics.yaml`; индексы0016. Публичная БД или deployment не требуются.

## Расчёты

- «Отправки» — все реальные строки попыток за период; replay не создаёт строку.
- Основная доля верных — последние ответы на каждое упражнение в каждом прохождении внутри периода: correct / (correct + incorrect). Pending отдельно, отсутствие оценённых ответов даёт null, не0%.
- «Ошибочных попыток» — все incorrect за период, включая исправленные. Поэтому это не число последних неверных ответов.
- Подсказки — уникальные раскрытия learning_hints за период для упражнений, на которые есть ответ в этом периоде. Доля с подсказкой использует последние ответы, включая pending. Раскрытия без отправленного ответа не входят в эту метрику.
- График по дням — все оценённые отправки в UTC, а не только последние. Отдельная доступная таблица содержит даты, знаменатели и числители. Возврат к задаче может улучшить последний результат и одновременно сохранить прошлые ошибки на графике.
- Темы берутся из immutable provenance банка; для обычных уроков из связанной темы. Одинаковые название/подтема объединяются в рамках разрешённой области. Это учебные признаки, не психометрическая оценка.
- Уровень: меньше5 оценённых ответов — мало данных; ниже70% — повторить;70–84,9% — закреплять; от85% — уверенный результат. Изменение — разность точности всех оценённых попыток во второй/первой половинах периода; показывается только при≥5 оценках в каждой, обе выборки видны.
- Домашние — назначения, созданные в период, text/material/legacy сохраняются. Done, submitted и просроченные несданные учитываются отдельно; это текущие статусы, не исторический журнал изменения статуса.
- Пробники — начатые в период; баллы raw по зафиксированным правилам11, pending отдельно. Активные экзамены не дают оценок, баллов, ошибок или рекомендаций. Просроченные study exams сервер завершает до чтения согласованного отчёта.

Ручная проверка обновляет текущее состояние оценивания. Отчёт использует repeatable-read snapshot, но не выдаётся за исторически неизменяемую ведомость оценок.

## Рекомендации и доступ

Объяснимое правило без LLM: последние неверные ответы группируются по теме и сортируются по числу ошибок; показывается размер выборки и причина (мало наблюдений, слабая тема или отдельные ошибки). Рекомендация указывает последнюю работу с такими ошибками; до20 конкретных условий и число попыток доступны без ключей. Повторение через API повторно проверяет актуальную ошибку, не доверяет устаревшему отчёту. Оно выбирает ошибки одной работы/версии, а не все упражнения всех работ по теме. Для следующей работы доступны остальные рекомендации и библиотека; интервальные тренировки относятся к13.

Ученик видит только себя. Преподавателю нужна активная связь в той же организации; дополнительно каждая попытка принадлежит его назначению, его программе пробника либо его обычному курсу без чужого assignment/study контекста. Два преподавателя одного ребёнка не видят закрытые результаты друг друга. Admin не получает неявный обход. Повторение использует ту же ресурсную область и существующую транзакцию назначения/уведомления. После отзыва связи кабинет преподавателя недоступен; собственная агрегированная история ученика сохраняется.
