## Рекомендуемый порядок

Актуальный порядок с 2026-10-29: последовательно 08–19 по явному разрешению пользователя; контрольная точка `CODEX_NEXT_RUN.md`. Следующие исторические рекомендации относятся к прежним назначениям номеров, не заменяют новую очередь.

1. Поддерживать воспроизводимость проверок при каждом изменении; отдельно закрывать ограничения API и auth-policy из первоначального аудита. Выполнение новых критериев 04/05 не означает production-hardening авторизации.
2. Закрыть основные пользовательские циклы (07–11), используя уже работающие core и связи (01, 02, 06).
3. Развивать мастерскую (12), затем файлы (13) и realtime (14) по отдельным задачам. Не заменять библиотеку уроков новой системой без согласования модели.
4. Довести общий UI (15), автоматическую приёмку (16) и восстановление (17). Проверки качества сопровождать каждым шагом, а не откладывать до конца.
5. Начать один согласованный V2-контекст (18) после стабилизации контрактов; не запускать все README-каркасы как будто они готовые сервисы. Приёмка 19 возможна на compatibility core, если это согласованный объём релиза.

## Границы

- По запросу от 2026-10-28 задача 07 назначена связи интерактивных материалов с домашними заданиями. Историческая реализация главной/профиля и незакрытая приёмка сохранения профиля остаются ограничениями аудита; смена номера не закрывает их автоматически.

- По явному запросу от 2026-10-19 задача 01 расширена: прежний подтверждённый Go baseline сохранён, новый критерий — backend каталога. Это не запуск задач 02–19 и не автоматическое подключение API к существующей HTML-мастерской. Ссылки следующих этапов на 01 включают сохранённую базу compatibility core.
- По следующему явному запросу от 2026-10-19 задача 02 назначена интерфейсу библиотеки поверх API 01. Исторические доказательства прямых миграций сохранены в трекере. API сейчас содержит только математику и не содержит поля длительности/обложки: UI не выдумывает эти данные. Старые HTML-интерактивы, импорт, отправка ответов ученика и автоматическая проверка остаются вне задачи 02.
- По отдельному запросу от 2026-10-19 задача 03 назначена универсальному движку упражнений и проверке ответов. Исторический frontend baseline сохранён в аудите трекера. Это не реализация агрегированного учебного прогресса, файлов решений, символьной алгебры или следующих задач.
- По следующему запросу от 2026-10-19 задача 04 назначена визуальным типам exercise-engine. Исторический аудит API сохранён; актуальные контракты расширяются вместе с реализацией. Geometry ограничена сеткой и заданными объектами, без аналога GeoGebra; числовая прямая в этой версии использует целый шаг. Следующие этапы автоматически не запускаются.

Прежние auth/security-критерии остаются незакрытыми ограничениями аудита (role, limiter, CSRF/Origin, SMTP), а не исчезают со сменой номера. Ссылки других этапов на 05 не подтверждают выполнение этих требований безопасности. Автономные HTML мастерской остаются вне серверного exercise-engine; прогресс сохраняется для материалов API каталога.
