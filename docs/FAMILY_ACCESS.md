# Родительский доступ

Используются отдельные ограниченные полномочия `guardian_links`, а не новая глобальная роль. Существующая роль аккаунта не меняется. Преподаватель или пользователь с обычным аккаунтом может также быть родителем, но только после отдельного приглашения от ребёнка. Никаких прав преподавателя это не добавляет. Вход в кабинет: Личный кабинет → Семья → Кабинет ребёнка.

## Подтверждение и отзыв

Ученик в разделе Семья явно разрешает просмотр учебных данных, указывает email родителя и создаёт личную ссылку. Ссылка передаётся адресату самим владельцем: автоматическая email-доставка не реализована. Приглашение действует7дней, токен256бит хранится только хешированным. В ссылке секрет находится во fragment, не в URL API/query/path; preview/accept передают его в JSON body авторизованного POST. Список связей никогда не возвращает токен/хеш. Не включать тела этих POST в диагностические логи.

Родитель входит в аккаунт с приглашённым email, видит ребёнка и явно подтверждает связь. Preview сам по себе разрешений не даёт; повторный accept того же пользователя безопасен. Другой email/организация, самостоятельное принятие ребёнком, истёкшая или отозванная ссылка запрещены. Приглашать может только сам ученик; преподаватель не выдаёт доступ от его имени. Ограничение10приглашений за серверные сутки. Неожиданная потеря ответа создания не раскрывает секрет повторно: приглашение можно отозвать и создать новое.

Отозвать связь может ученик или принявший приглашение родитель. Отзыв идемпотентен; прежний токен не активирует связь заново. После отзыва закрываются отчёт, учебные события/прочтение и даже список текущих имён детей для этого родителя. История своих отправленных приглашений остаётся у ученика. Родитель A с разрешённым ребёнком A не может смотреть ребёнка B родителя B, даже заменив ID. Admin не получает неявного исключения.

Это техническое подтверждение доступа по приглашению, не независимая проверка родства, возраста или личности. Историческая регистрация приложения ещё не гарантирует подтверждение email; секретную ссылку следует передавать реальному адресату. Вопросы правил доступа несовершеннолетних и проверки полномочий должны быть отдельно решены владельцем перед публичным запуском, а не подменены галочкой интерфейса.

## Разрешённые данные

Родитель получает отдельную allowlist-проекцию по активной связи в текущей организации:

- Расписание: название, преподаватель, начало/конец, статус.
- Домашние задания: название/предмет/тема, срок, статус и оценка. Черновики/архив скрыты; тело задания, текст ответа и обычный feedback не передаются.
- Native упражнения: условие, последний статус, число отправок за выбранный период; без ответов ученика, ключей и решений.
- Метрики/темы/график из общих серверных правил аналитики12, с sample size и отдельными pending. Незавершённые контрольные исключены.
- История завершённых пробников: первичные баллы и ожидающие ручной проверки; без официальной шкалы и доступа к student session endpoint.
- Только отдельно опубликованные для родителей комментарии преподавателей с действующей связью. Обычные заметки/feedback не открываются автоматически; автор может снять комментарий с публикации.
- Учебные события после подтверждения связи: расписание/задание, сдача/оценка, завершение native прохождения/ручная проверка, опубликованный комментарий. Отдельный журнал `guardian_events` не копирует личные уведомления ребёнка или сообщения.

Существующие API расписания, чата, заданий, проверки, прогресса и аналитики не расширены до родителя. Нельзя решать за ребёнка, изменять задания или читать переписку. Семейный grant проверяется на backend в read-only snapshot, а не только скрытием кнопок. Нет impersonation: отчёт не вызывает student API под подставленным actor.

По умолчанию период от29дней назад до30дней вперёд, чтобы сразу видеть ближайшие занятия/сроки. Его можно выбрать вручную, максимум366календарных дней. Семь независимых страниц по20: темы/пробники/занятия/задания/комментарии/события/результаты. График по UTC, отображаемые даты — локальные. Число отправок результата относится к выбранному периоду.

События записываются транзакционными DB triggers только при наличии активного родителя; повтор update без смыслового изменения их не дублирует. Сдача и проверка не порождают второе событие изменения статуса задания. Отметка прочтения — серверное время в связи. Лента с unread находится в кабинете ребёнка; push/email-доставка и объединение с основным bell не реализованы. Старые события до подключения нового родителя не показываются. Legacy HTML не становится источником достоверных баллов.

## API

- `GET /api/v1/family/links?limit=20&offset=0` — свои приглашения ученика и активные принятые связи родителя.
- `POST /api/v1/family/invitations` — `{guardian_email,confirm_share:true}`, только ученик; ответ `{link,accept_url}`.
- `POST /api/v1/family/invitations/preview` и `/accept` — `{token}`, только приглашённый аккаунт.
- `POST /api/v1/family/links/{linkID}/revoke` — `{}`, участник связи.
- `GET /api/v1/family/children/{studentID}` — `from/to` (YYYY-MM-DD), независимые `topic_offset`, `exam_offset`, `lesson_offset`, `assignment_offset`, `note_offset`, `event_offset`, `result_offset` (0–100000).
- `POST /api/v1/family/children/{studentID}/read` — `{}`, только активный родитель.
- `POST /api/v1/family/notes` — `{student_id,body,request_id}`, только связанный преподаватель; nonce повторяет запись, изменённый payload409.
- `GET /api/v1/family/students/{studentID}/notes?limit=20&offset=0` — только собственные опубликованные комментарии связанного преподавателя.
- `POST /api/v1/family/notes/{noteID}/withdraw` — `{}`, только автор.

Неизвестные/server-owned входные поля отклоняются. Исходная миграция0019, allowlist DTO в `domain/family.go`, контракт `family.yaml`. Обратная миграция с данными требует экспорта и намеренно отказывается удалять связи/заметки/события.
