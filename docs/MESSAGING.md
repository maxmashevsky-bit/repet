# Мессенджер

## Текущая интеграция, 2026-10-30

Поверх проверенной основы0020 реализована0021: приватные файлы, ссылки на задания и опубликованные native уроки, просмотр условия задания в переписке. Выбор вложения — скрепка рядом с полем сообщения, затем «Файл», «Задание» или «Урок». Один ресурс на сообщение; текст необязателен только при наличии вложения. Старый messages_body_check обновлён, иначе такие сообщения ошибочно давали500. Текстовые assignments теперь имеют отдельный рабочий reader `/tasks/{id}`; старые `/tasks?task={id}` открывают его же. Из уведомлений доступны ответ, ручная проверка и результат, не только общий список.

### Приватные файлы

POST conversations/{id}/files принимает filename/data(base64)/request_id, GET files/{fileID} скачивает, DELETE удаляет только собственный неотправленный файл. Точные пути и DTO в `chat-attachments.yaml`. Допускаются PNG/JPEG/TXT;≤4МиБ, bitmap≤4Мпикселей, квота50МиБ/100файлов на владельца под DB advisory lock. Проверяется содержимое, а не заявленный MIME. Изображение декодируется и пересобирается без метаданных и trailing payload. TXT — UTF-8 без бинарных/control/format символов; отдаётся text/plain как attachment. Это узкий CDR/allowlist, **не универсальный антивирус**. HTML/SVG/PDF/office/архивы/exe отклоняются. См. ADR0004: не расширять список без карантина/scanner policy.

Ключ ObjectStorage и хеши не возвращаются. До отправки файл доступен только uploader; после — двум действующим участникам. Peer/admin/guardian и другая переписка не открывают файл. Отзыв relation закрывает скачивание. Аудируются upload/download/delete. Pending живёт24ч, удаляется явной отменой либо при следующей загрузке владельца; attached immutable. При неопределённом commit объект не удаляется без проверки наличия metadata. Общий orphan reconciler/production S3 остаются эксплуатационной работой, как и AV для иных форматов.

### Ресурсные ссылки

GET conversations/{id}/references?kind=assignment|lesson&q=...&offset=... —20ресурсов, доступных **обоим** участникам. Assignment должен принадлежать именно паре tutor/student, не draft/archive. Native урок — только опубликованный, с опубликованными course/предками, не assignment_only; приватный чужой курс не раскрывается. Отправка проверяет IDs повторно, не создаёт grants. Preview assignments/{id} содержит только id/title/body/kind/status/due_at, без student answers/feedback/закрытых ключей.

Message nonce фиксирует body и все attachment IDs. Идентичный replay возвращает прежние ID/sequence, другойpayload409. DB trigger дополнительно проверяет связи файлов и ресурсов, сообщения неизменяемы. После архивирования ссылки title/id не выдаются и UI показывает недоступность. Входящий poll не стирает pending/retry с вложением. Новые файлы и выбранные ресурсы сохраняются при переключении диалога в памяти страницы, как и текст; полноценного offline-outbox между закрытиями вкладки нет.

## Переписка и прочтение

Миграция0020 задаёт каждому сообщению монотонную `sequence` внутри диалога. Старые сообщения получают стабильный порядок по created_at/id; новые сериализуются row lock диалога, время задаётся БД. Нельзя потерять unread из-за транзакции, начавшейся раньше отметки прочтения, но завершившейся позже. Пропуски номеров после идемпотентного replay допустимы: unread считается по реальным строкам, не вычитанием счётчиков.

`GET /api/v1/messages/conversations` возвращает до100 действующих диалогов участника с `unread_count` (только чужие сообщения после cursor). `GET /api/v1/messages/conversations/{id}?offset=0` — до80 сообщений, внутри страницы по возрастанию sequence. Для обоих требуется активная связь того же преподавателя/ученика/организации. Admin без участия и guardian grant не открывают личный чат.

`POST /api/v1/messages/conversations/{id}/read` принимает только `{through_message_id}`. Backend получает sequence из сообщения этого диалога и продвигает только cursor текущего пользователя. Меньшая отметка не двигает его назад; будущий/чужой ID404; время, user_id и last_sequence от браузера не принимаются. DB trigger дополнительно запрещает постороннего участника/обратный cursor. Ответ — реальный `unread_count`, а не предположение React.

Отправка с тем же `Idempotency-Key` и тем же body возвращает прежнее сообщение/sequence; другой body409. Лимит4000 Unicode-кодовых точек, без принятия author/organization/created_at от клиента. Уведомление о новом сообщении использует прежний unique message key и ссылку на конкретный диалог.

## Обновление интерфейса

- Активная переписка:5с; список диалогов:15с; личные уведомления:20с.
- Один запрос за цикл, отмена при скрытии/отключении, пауза скрытой вкладки, backoff10/20/40/60с после ошибок, сброс после успеха. Ручное обновление доступно при ошибке.
- Входящие страницы объединяются по ID и server sequence; старый poll не стирает более новую отправку. Запоздалые ответы списка/notifications не отменяют более новое прочтение/refresh.
- Прочтение только в активном видимом/focused чате у нижнего края ленты, после layout frame. Скролл к истории не потребляет новые сообщения автоматически.
- Черновики отдельные для диалогов. Уже использованные чаты сохраняются в памяти страницы при переключении, но скрытые не poll/read. Это также сохраняет failed-send пузырь и nonce для повторной отправки. При отзыве связи недоступный чат удаляется из UI.
- Потерянный ответ сервера можно перепроверить кнопкой повторной отправки с прежним nonce: сервер не создаёт дубль. Черновики/ошибки пока не переживают закрытие всей страницы или вкладки, это не серверный offline outbox.

`features/messages/polling.ts` — тестируемый scheduler с явным окружением, `usePolling` — React/browser adapter. Общий API client и AppShell сохранены. Никаких Telegram/внешних realtime providers или новых dependencies.

## Следующий шаг

Прочитаны ADR0004 и ObjectStorage: приватное S3-compatible storage — production boundary, локальный adapter требует upload scanning controls. Следующий исполнитель должен сначала определить безопасную allowlist и проверку содержимого/сканирование, затем добавить upload/download с лимитами, квотой, приватными ключами, ACL диалога/участника и lifecycle неотправленных файлов. Не выдавать MIME sniff/extension за полноценный антивирус и не делать raw HTML/SVG/JS доступными на origin приложения. Уже существующий PDF import не является универсальным антивирусом для чат-вложений.

После файлов: проверяемые ссылки на назначение/учебный урок с правами обоих участников, preview задания из чата, уведомления сдачи/проверки и deep links. Нужен полный двухпользовательский browser-тест с вложениями до DONE15; нынешний messages E2E проверяет только основу polling/read/retry/drafts.
