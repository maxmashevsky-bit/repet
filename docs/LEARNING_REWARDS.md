# Повторение и достижения

В разделе Задания → Повторение ученик открывает план на сегодня, работу над ошибками и короткие квизы. Преподаватель выбирает связанного ученика, видит его контекст и может отключить XP и награды, не отключая обучение. Верхняя навигация остаётся из четырёх разделов.

## Очередь повторения

Используются только завершённые native прохождения. Для каждого логического упражнения и преподавательского контекста выбирается последнее наблюдение: неправильное или оставленное без ответа предлагается сразу, правильное — через1/3/7/14/30дней после1/2/3/4/5 самостоятельных дней решения без hints и предыдущей ошибки в том же прохождении. Даты и вердикты берутся с сервера. Поздняя ручная проверка старого ответа не вытесняет более новый ответ; её время учитывается при назначении срока повторения. Pending показывается отдельно и не превращается в ошибку. Активная контрольная не раскрывает результаты через план повторения.

Квиз выбирает1–10 упражнений одной исходной версии/темы, без повторов внутри варианта. `learning_review_sessions` сохраняет immutable grant на завершённый исходный run и выбранные exercise_keys. Повторный квиз ссылается на плоский исходник, а не цепочку разрешений. Ответы, hints, навигация, ручная проверка и продолжение вкладки используют существующий LearningPlayer/API05–06. Nonce возвращает прежнее прохождение, несовпадающий payload даёт409. Новую тренировку нельзя открыть поверх активной работы того же урока.

Прочтение и отправка повторно проверяют исходный доступ: выбранные задания назначения, курс программы и действующая связь. Отзыв исходного доступа закрывает также квиз и native `current`. Частная банковская подборка не становится целиком доступна из-за одного назначенного упражнения; DB trigger дополнительно запрещает ответы вне выбранного набора. Ручной ответ идёт преподавателю контекста, а не автору общей заготовки. Без активного проверяющего такой квиз не создаётся.

В интерфейсе есть незавершённые тренировки, независимая пагинация плана и активных работ, реальная недельная цель3 завершения, краткое освоение тем из аналитики12 с числом оценённых ответов, отдельные pending и ссылка на полную статистику. Это объяснимое расписание повторений и эвристика освоения, не психологическая оценка памяти. Уровень XP не равен освоению темы. Legacy HTML не участвует в доверенной статистике; для него нужна native конвертация08–09.

## Проверяемые правила

XP не приходит из браузера. Используются завершённые native прохождения, серверные попытки, hints и ручные вердикты преподавателя. Для одного логического исходного упражнения нужны первые верные ответы без подсказок в двух прохождениях на разных UTC-днях с интервалом минимум24часа. Numeric/text допустимы; long_text только после ручного correct. Выбор вариантов и все визуальные типы пока не награждаются: по одному выбору нельзя надёжно отличить понимание от угадывания. Это ограниченное правило подтверждённого повторения, не детектор намерений ребёнка.

Ошибка, затем правильный ответ в том же прохождении не считаются самостоятельным первым решением. Replay не создаёт попытку или награду. Source lesson/exercise берутся из bank provenance либо исходного exercise_key, поэтому копии и версии не создают повторный XP. Уникальная неизменяемая запись журнала даёт10XP один раз за исходное упражнение. Время достижения не раньше завершения и ручной проверки; неделя начинается в понедельник UTC. Уровень:1+floor(XP/100), прогресс до следующих100XP. Ни рейтингов детей, ни соревнования нет.

Настройка принадлежит контексту преподаватель→ученик и требует активной связи той же организации. Она отключает начисление и показ его наград, не затрагивая разрешённые контексты других преподавателей. При всех отключённых активных преподавателях ученик не видит игровые показатели. Повтор PUT не меняет timestamp. После включения новые награды не начисляются задним числом за период отключения; прежние достижения сохраняются в ledger и снова доступны. Учебная аналитика/материалы от этой настройки не зависят.

Начисление ленивое при чтении rewards API под существующим student learning lock, не на стороне React. Бейджи отображают реальные записи ledger; анимация завершения учитывает reduced-motion. Отключение не скрывает статистику решений. Настройка не является запретом самостоятельной практики в контексте другого разрешённого преподавателя.

## API

- `GET /api/v1/learning-reviews/{studentID}?mode=due&limit=20&offset=0&active_offset=0` — собственный или преподавательский план; `mode=errors/all`, независимая страница active по20.
- `POST /api/v1/learning-review-sessions` с `request_id`, `source_run_id`, необязательным `topic_key`, `mode=due/errors/quiz`, `count=1..10` — только ученик, закреплённый quiz.
- `GET /api/v1/learning-review-sessions/{reviewID}` — собственное сохранённое состояние без закрытых ключей.
- `GET /api/v1/learning-review-checks?limit=20&offset=0` — очередь текущего преподавателя; вердикт через существующий catalog lesson attempts review endpoint.
- `GET /api/v1/learning-rewards/{studentID}?limit=20&offset=0` — собственные показатели ученика либо только контекст связанного преподавателя, пагинация ledger.
- `GET /api/v1/learning-rewards/{studentID}/preference` — настройка текущего преподавателя, default enabled.
- `PUT /api/v1/learning-rewards/{studentID}/preference` с `{ "enabled": false }` — только преподаватель; неизвестные server-owned поля запрещены.
