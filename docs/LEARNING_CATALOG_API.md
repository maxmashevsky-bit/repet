# Задача 01: backend учебного каталога

Базовый префикс: `/api/v1/catalog`. Все маршруты требуют существующую cookie-сессию `repet_session`. Это API внутри `services/core`, не новый frontend-раздел и не отдельный сервис. Календарная таблица `lessons` и её API не изменены. OpenAPI: `packages/contracts/openapi/learning-catalog.yaml`, подключён к основному compatibility-контракту.

## Модель и права

- `courses`: автор из сессии, организация, название/описание, направление, классы, сложность, доступность и статус.
- `topics`: дерево тем внутри курса. `parent_id` — null либо тема того же курса; циклы запрещены. Автор наследуется от курса.
- `learning_lessons`: идентификатор материала, автор, курс, статус и указатель текущей публикации. Не календарное занятие.
- `lesson_versions`: версия 0 — рабочий черновик. Номера 1+ — отдельные опубликованные снимки текста, названия, темы, направления, классов и сложности.
- `exercises`: вопросы и варианты ответа конкретной версии. Публичный `id` — стабильный `exercise_key`; физические строки упражнений копируются при публикации.
- `exercise_answer_keys`: ответы и закрытые пояснения к физической строке упражнения; никогда не входят в DTO материала, списка версий или упражнения.

Направления `track`: `school`, `olympiad`, `oge`, `ege`. Вся эта библиотека относится к математике. Классы: `1 <= grade_min <= grade_max <= 11`. Сложность: целое 1–5. Курсы и уроки имеют собственные классификационные поля: поиск материалов использует поля выбранной версии урока, а не текущие поля курса.

Автор-преподаватель создаёт и изменяет только свои ресурсы своей организации. Другой преподаватель не получает доступ к черновикам, истории версий и ключам. У `admin` нет неявного обхода этих правил. Клиент не задаёт `author_id`, `organization_id`, `role`, `owner_id`, `created_by`, `permissions` и статус в теле создания/редактирования: неизвестные поля отклоняются.

Доступ по умолчанию — `visibility: linked_students`: ученик должен иметь активную связь с автором. Автор может явно выбрать `organization`: опубликованные ресурсы доступны ученикам и другим преподавателям той же организации. Между организациями доступа нет. Для чтения неавтором должны быть опубликованы курс, выбранная тема, все её предки и сам материал. Архивация курса/ветки скрывает дочерние материалы без удаления версий. Блокировка/завершение связи отнимает linked_students-доступ.

## Версии

`GET /lessons/{id}` и списки для автора возвращают черновик 0; для остальных читателей — только текущую публикацию. `has_unpublished_changes` полезен автору; для других читателей всегда false. Содержимое `content` — текст/Markdown, не исполняемый HTML. Ответ API не должен напрямую вставляться в DOM как HTML.

`POST /lessons/{id}/publish` в одной транзакции копирует черновик, упражнения и ключи, запечатывает снимок и переключает указатель публикации. Ответ содержит созданную опубликованную версию. Редактирование после публикации меняет только черновик. Повторная публикация без изменений возвращает 422; из двух одновременных публикаций одного черновика проходит одна. Републикация архива создаёт новый снимок.

Блокировка строки курса сериализует изменения дерева, содержимого и публикации. Триггеры БД запрещают UPDATE/DELETE опубликованных версий, упражнений и ключей, а также дописывание упражнений/ключей в запечатанный снимок, включая старую публикацию после появления следующей. Изменение текущей доступности или имени автора не переписывает сохранённый текст версии.

Автор получает историческую публикацию через `/versions/{number}` и список `/versions`. Неавтор может получить только текущую доступную публикацию, не номер 0 и не предыдущие публикации.

## Маршруты

| Метод | Путь относительно префикса | Назначение |
| --- | --- | --- |
| POST / GET | `/courses` | Создание черновика / поиск доступных курсов |
| GET / PUT | `/courses/{courseID}` | Получение / замена полей своего курса |
| POST | `/courses/{courseID}/publish` | Публикация или восстановление курса |
| POST | `/courses/{courseID}/archive` | Архивация курса |
| POST / GET | `/courses/{courseID}/topics` | Создание / поиск доступных тем |
| GET / PUT | `/topics/{topicID}` | Получение / редактирование темы и родителя |
| POST | `/topics/{topicID}/publish` | Публикация темы при опубликованных предках |
| POST | `/topics/{topicID}/archive` | Архивация ветки |
| POST | `/courses/{courseID}/lessons` | Создание учебного материала |
| GET | `/lessons` | Поиск доступных материалов |
| GET / PUT | `/lessons/{learningLessonID}` | Получение доступной версии / изменение своего черновика |
| POST | `/lessons/{learningLessonID}/publish` | Создание неизменяемой публикации |
| POST | `/lessons/{learningLessonID}/archive` | Скрытие материала |
| GET | `/lessons/{learningLessonID}/versions` | Пагинированный список доступных публикаций |
| GET | `/lessons/{learningLessonID}/versions/{number}` | Конкретная разрешённая версия |
| POST / GET | `/lessons/{learningLessonID}/exercises` | Создание упражнения / пагинированное чтение без ключей |
| GET / PUT | `/lessons/{learningLessonID}/exercises/{exerciseID}` | Чтение / редактирование своего упражнения |
| GET | `/lessons/{learningLessonID}/answer-keys?version=0` | Только автор: закрытые ключи черновика или указанной публикации |

PUT заменяет редактируемые поля целиком. Тело publish/archive — `{}` либо пустое. Статусы меняются только отдельными действиями. Ответы: 201 при создании, 200 при чтении/изменении, 400 при неверном теле/фильтре/UUID/цикле, 401 без сессии, 403 при запрещённой роли записи, 404 для отсутствующего или недоступного объекта, 422 для неподготовленной/неизменённой публикации. Стандартный конверт ошибки core сохраняется.

## Поиск и пагинация

Все списки: `limit=20` по умолчанию, 1–100; `offset=0`, 0–100000. Ответ: `{items: [], total: 0, limit: 20, offset: 0}`. `total` считает только доступные ресурсы и остаётся корректным за концом списка. Сортировка стабильна: курсы/материалы created_at DESC + id, темы/упражнения position + id, версии number DESC.

- Курсы: `q`, `track`, `grade`, `difficulty`, `author_id`, `status`.
- Темы внутри курса: `q`, `status`.
- Материалы: `q`, `track`, `grade`, `difficulty`, `author_id`, `course_id`, `topic_id`, `status`. Фильтр темы включает её подтемы. Поиск учитывает текст/название/краткое описание доступной версии, не закрытые ключи. Используется русский full-text поиск и буквальное подстрочное совпадение.
- Упражнения: `q`, `difficulty`.
- Версии: только `limit`, `offset`.

Неизвестные, повторные и недопустимые query-параметры списков возвращают 400. У неавтора фильтр `status=draft` или `archived` не открывает скрытые данные.

## Минимальный сценарий API

Под существующей сессией преподавателя:

1. `POST /courses` с телом:

```json
{"title":"Математика 5–6","description":"Курс рассуждений","track":"olympiad","grade_min":5,"grade_max":6,"difficulty":2}
```

2. `POST /courses/{courseID}/topics`: `{"title":"Чётность","parent_id":null,"position":0}`.
3. `POST /courses/{courseID}/lessons`:

```json
{"topic_id":"UUID темы","title":"Сумма чётных чисел","summary":"Исследуем закономерность","content":"Сформулируйте свойство суммы.","track":"olympiad","grade_min":5,"grade_max":6,"difficulty":2}
```

4. `POST /lessons/{id}/exercises` (ключ передаётся только в авторском запросе):

```json
{"kind":"single_choice","prompt":"Сумма двух чётных чисел?","options":["Чётная","Нечётная"],"difficulty":1,"position":0,"answer_key":{"answer":"Чётная","explanation":"2a + 2b = 2(a+b)."}}
```

5. Опубликовать курс, затем тему (сначала её предков, если есть), затем материал.
6. Под сессией связанного ученика `GET /lessons/{id}` вернёт публикацию с упражнениями, но без answer_key/answer/explanation. Получение закрытых ключей запрещено. Дальнейшие PUT автора не меняют этот ответ до новой публикации.

Типы упражнений: `text`, `numeric`, `single_choice`. Для single_choice нужны 2–12 уникальных непустых вариантов; закрытый ответ должен совпадать с вариантом. Для text/numeric options пуст. Числовая автопроверка и отправка ответов учениками не входят в задачу 01.

Позиция темы/упражнения — 0–1000000. Номер запрашиваемой версии — 0–2147483647; превышение диапазона возвращает 400.

## Проверка

`TestLearningCatalogPostgres` выполняет HTTP-сценарий с настоящей PostgreSQL и сессиями, negative ACL, запрет server-owned полей, дерево тем, редакции и ключи, параллельную публикацию, поиск/пагинацию/архивацию. Отдельные SQL-попытки изменить опубликованные данные должны возвращать 23514. Тест требует TEST_DATABASE_URL на отдельную тестовую БД; без него SKIP, не PASS интеграции.
