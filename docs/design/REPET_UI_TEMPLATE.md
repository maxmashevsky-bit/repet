# Репет: шаблон интерфейса

Использовать этот документ вместе с `apps/web/app/styles.css`, `apps/web/features/ui/Brand.tsx` и `apps/web/features/app-shell/AppShell.tsx` при создании любой страницы «Репет». Референс — существующая главная страница из предоставленного скриншота. Это спецификация для разработки и дизайна, а не текст для отображения внутри приложения.

## Визуальное направление

Спокойный, светлый личный кабинет для занятий. Тёплый почти белый фон, глубокий зелёный для действий, графитовый текст, тонкие светлые границы. Оранжевый — небольшой акцент логотипа и отдельных учебных статусов. Чёткая иерархия, много пространства между смысловыми блоками, компактные элементы управления. Содержимое и действия важнее декора.

Сохранять узнаваемость скриншота: логотип слева, навигация по центру, уведомления и профиль справа, заголовок над рабочей областью. Не превращать сообщения, календарь и задания в рекламные страницы с большими баннерами.

Белый текст на зелёной основной кнопке. Важные ошибки сопровождать текстом и значком; светлые статусные оттенки использовать для подложки, а не мелкого текста. Не передавать статус только цветом. Не вводить новую палитру для каждой страницы.

Для уже существующего зелёного блока ближайшего занятия допустим текущий фон `linear-gradient(125deg, #507F64 0%, #356B50 66%, #2F6249 100%)`. Не распространять градиент на формы, таблицы, диалоги и весь экран.

## Шрифты и размеры

Шрифтовой стек проекта:

```css
font-family: "Manrope", "Inter", -apple-system, BlinkMacSystemFont,
  "Segoe UI", sans-serif;
```

Manrope — целевой шрифт макетов, с кириллицей и начертаниями 400–800. Сейчас в приложении этот стек объявлен, но Manrope и Inter отдельно не подключены: браузер может показывать системный шрифт. Для точного совпадения макета и сайта требуется единое подключение шрифта; не считать его уже загруженным.

| Элемент | Desktop | Mobile | Насыщенность / интерлиньяж |
| --- | --- | --- | --- |
| Название бренда | 30 px | 25–27 px | 800 / 1 |
| H1 страницы | 40 px | 30 px | 750–800 / 1.15 |
| Заголовок ближайшего занятия | 40 px | 30 px | 700 / 1.15 |
| H2 секции | 22 px | 20 px | 700 / 1.3 |
| Заголовок компактного блока | 18 px | 18 px | 700 / 1.35 |
| Основной текст | 15–16 px | 15–16 px | 400–500 / 1.5 |
| Навигация и кнопки | 16 px | 15 px | 600–700 / 1.3 |
| Подпись поля | 14 px | 14 px | 600–700 / 1.4 |
| Даты и метаданные | 12–13 px | 12–13 px | 400–500 / 1.45 |

Это фиксированная шкала для новых страниц; некоторые старые стили используют другие размеры. Межбуквенный интервал новых элементов — `0`. Не масштабировать шрифт через `vw`. Длинные заголовки переносятся; имена в шапке сокращаются многоточием, полное имя доступно в профиле. Не уменьшать весь интерфейс ради длинного текста.

## Сетка и оболочка

- Desktop: рабочая ширина до 1480 px, поля по 32 px, шапка 84 px, отступ контента сверху 34 px.
- До 1180 px: поля 20–24 px, верхнее меню заменяется кнопкой открытия навигации.
- До 820 px: шапка 68 px, поля 12–16 px, контент сверху 24 px, основные колонки складываются вертикально.
- Базовый шаг отступов: 4 px. Использовать 8, 12, 16, 24, 32, 48 px.
- Между самостоятельными секциями — 24–32 px; между заголовком и содержимым — 16–24 px; между полями формы — 16 px.
- Радиусы текущей системы: 10 px для полей и кнопок, 16 px для существующих крупных блоков. Не добавлять произвольные новые радиусы. Круг — для аватара и круглой кнопки-иконки.
- Основные разделы оформлять открытой сеткой или с разделителями. Карточка подходит отдельному заданию, событию, диалогу или модальному окну. Не вкладывать карточки в карточки и не обводить каждый абзац.
- Тень только при реальном наложении: меню, popover, модальное окно. Базовая тень проекта: `0 12px 36px rgba(67, 55, 43, .08)`.

Верхняя навигация строго: **Главное / Сообщения / Календарь / Задания**. Активный пункт зелёный, с нижней линией 3 px. Настройки открываются через профиль. Отдельной страницы «Материалы» нет: файлы относятся к уроку, сообщению или заданию.

## Логотип и иконки

Использовать готовые `Brand` и `BrandMark`. Знак — зелёная буква «Р» с оранжевой страницей; название только «Репет». Не перерисовывать и не растягивать знак. Размер знака в шапке: 40 × 40 px, на мобильном — 32 × 32 px. Декоративный большой знак допустим только в существующем блоке ближайшего занятия и на экранах авторизации, вне зоны чтения и нажатий.

В коде использовать существующий компонент `Icon`. Иконки одного семейства, обычный размер 20–24 px, в компактных ссылках 16–18 px. Кнопки-иконки имеют понятный `aria-label` и подсказку при наведении. Не использовать эмодзи вместо системных иконок.

## Компоненты

### Кнопки и ссылки

- Primary: зелёная заливка `#3F7659`, белый текст, высота минимум 44 px, горизонтальные отступы 18 px.
- Secondary: прозрачный фон, текст `#2F2A24`, тонкая граница `#B9B0A6`.
- Text action: зелёный текст; стрелка справа, если действие открывает другую страницу.
- Icon button: 44 × 44 px, иконка по центру, ненавязчивый фон при наведении.
- Во время сохранения блокировать повторную отправку, сохранять размер кнопки. Disabled визуально различим и действительно недоступен.
- Одно главное действие на рабочую область. Иконка для закрытия, назад, переключения периода, скачивания; текст для «Сохранить», «Создать задание», «Отправить».

### Поля и формы

Высота поля минимум 46 px, внутренние отступы 12 × 14 px, граница 1 px, подпись над полем. Подсказка и ошибка под соответствующим полем. Placeholder не заменяет label. Ошибка не стирает введённые значения. Пароль имеет кнопку показа. Радиокнопки или segmented control для выбора роли, checkbox для согласия, переключатель для бинарной настройки.

Состояние фокуса: `0 0 0 3px rgba(94, 133, 101, .23)`. Клавиатурный фокус всегда заметен. Для опасных действий — явное название и подтверждение по месту действия.

### Списки, статусы и данные

Стабильная структура строк: основное название, метаданные, статус, действие. Метаданные не конкурируют с названием. Использовать реальные даты и часовой пояс пользователя. Нули и пустые списки — нормальное состояние, не подставлять вымышленные уроки и достижения.

Задания: «Назначено», «Отправлено», «На доработке», «Проверено», «Просрочено». Уроки: дата, время, ученик или преподаватель, тема, статус. У статуса есть текст, а не одна цветная точка.

### Состояния любой страницы

1. Загрузка: стабильная геометрия, нейтральные skeleton-элементы, без прыжков контента.
2. Есть данные: основной рабочий интерфейс и актуальные действия.
3. Нет данных: короткое сообщение и подходящее действие, например «Занятий пока нет» и «Создать занятие» для преподавателя.
4. Ошибка: понятная причина, сохранённый контекст, «Повторить».
5. Отправка: занято только соответствующее действие, без повторных запросов.
6. Успех: краткий результат рядом с действием, обновлённые данные.
7. Нет доступа или истекла сессия: явный экран с нужным переходом, без раскрытия чужих данных.

## Шаблоны страниц

| Страница | Общая композиция | Ученик | Преподаватель |
| --- | --- | --- | --- |
| Главное | Заголовок; ближайшее занятие и сегодняшний день; недельная полоса; короткие рабочие списки | Задания к сдаче, следующий урок, последние сообщения | Сегодняшние ученики, работы к проверке, создание занятия и приглашение |

| Календарь | Панель периода и вида, сетка календаря, подробности выбранного события | Просмотр доступных занятий | Создание занятия и управление разрешёнными событиями |
| Задания | Заголовок и фильтры, список, подробности выбранного задания | Ответ, отправка, статус и обратная связь | Создание, просмотр ответа, оценка и доработка |
| Настройки | Список разделов и форма, сохранение рядом с изменяемыми данными | Профиль, часовой пояс, уведомления, безопасность | Та же система с полями, разрешёнными роли |
| Вход | Бренд, компактная форма, ссылка на восстановление и регистрацию | Общая форма входа | Общая форма входа |
| Регистрация | Бренд, выбор роли, имя, email, пароль, согласие | Выбран «Ученик» | Выбран «Преподаватель» |

| Приглашение | Кто приглашает, состояние приглашения, одно действие принятия | Принятие подходящим аккаунтом | Создание приглашения в кабинете |
| Конфиденциальность | Узкая колонка читаемого текста, заголовки и дата редакции | Одинаковая страница | Одинаковая страница |

На мобильном в сообщениях показывать либо список, либо диалог с кнопкой назад. В календаре использовать читаемый день или список событий; если нужна широкая недельная сетка, прокручивать только её, а не всю страницу. В заданиях подробности открываются отдельной областью с понятным возвратом. Не сжимать desktop-сетку до нечитаемых колонок.

## Каркас новой страницы в проекте

Новый рабочий экран помещается внутрь существующего `AppShell`: не добавлять повторно шапку, footer или второй запрос сессии. Данные и обновление доступны через `useWorkspace()`, предметные запросы — через `productApi`.

```tsx
"use client";

import { useWorkspace } from "../app-shell/AppShell";

export function ExamplePage() {
  const { dashboard } = useWorkspace();

  return (
    <section>
      <div className="page-title">
        <h1>Название страницы</h1>
        <p className="muted">Контекст текущих данных</p>
      </div>
      {/* Рабочее содержимое с учётом dashboard.user.role. */}
    </section>
  );
}
```

Это каркас размещения, а не готовая функциональная страница. Описания дизайна, названия CSS-переменных и инструкции для разработчика не выводить пользователю.
